This file tracks items deliberately deferred from launch signoff. Create matching
GitHub issues for each item before V1 ships; the local environment currently
does not have the GitHub CLI installed, so these are issue-ready stubs.

## Explicitly Excluded From Current Launch Sprint

Status: DEFERRED / TRACKED

These items are important, but they are deliberately excluded from the current
engineering slice so they do not blur the trust-chain blocker list:

- Live deploy of privacy/terms pages to `drapeon.co`
- Real-device QA for account deletion, email change, payment failure, payout
  release, and production-stall automation
- App Store / Play Store screenshots, copy, data safety, and metadata pack

Decision:
Keep these visible for launch operations, but do not treat them as active code
work in the current sprint slice.

## V1.1-001 Reverse Logistics Automation

Status: DEFERRED TO V1.1

Scope:
- define return-to-tailor vs return-to-Drape
- define who pays return shipping by fault type
- add reverse-logistics timeline statuses

## V1.1-002 Full Group-Order Engine

Status: DEFERRED TO V1.1

Scope:
- decide parent-order plus child-order model
- recipient-level measurement capture
- recipient-level garment tracking
- dye-lot and fabric controls

Reason:
Bulk custom is launch-supported only as an ops-managed special case. Shipping a
partial group-order engine would make measurements, privacy, and order status
harder to trust.

## V1.1-006 Accessibility Hardening

Status: DEFERRED TO V1.1, WITH BASIC V1 CHECKS BEFORE STORE SUBMISSION

Scope:
- run a full screen-reader pass across customer, tailor, auth, order, payout,
  and messaging flows
- add missing `accessibilityLabel`, `accessibilityRole`, and
  `accessibilityHint` props to raw pressables and icon-only controls
- enforce accessible image labels or decorative-hidden behavior for every image
- verify every touch target is at least 44 x 44 pt, with primary actions at
  52 pt
- fix contrast failures for muted text and white text on brand/accent colors
- test largest system font size for overflow and clipped buttons
- add accessibility review notes to the manual QA runbook

Reason:
The app has partial accessibility support through shared inputs/buttons and some
newer screen-level labels, but it has not had a complete assistive-tech,
contrast, and text-scaling pass. That is not honest enough to mark as production
complete.

2026-05-09 note:
Basic V1 tightening has started: message composer controls and customer/tailor
tab buttons now have explicit roles/labels, and message composer icon buttons
meet the 44pt touch target minimum. The full screen-reader and contrast pass
remains V1.1 unless release-device QA exposes a launch-blocking issue.

## V1.1-007 Localization And Translation Foundation

Status: DEFERRED TO V1.1

Scope:
- introduce a translation string catalog and `t()` helper before translating
  user-facing copy
- keep dates, currency, and numbers locale-aware
- separate legal/store copy from in-app product copy
- decide first supported non-English languages based on launch geography and
  support capacity
- make support templates translation-ready before enabling translated UI

Reason:
V1 can launch English-only if store listings and support expectations say so.
Full translation is valuable for Drape's long-term audience, but shipping
partially translated checkout, payment, dispute, or support flows would reduce
trust rather than increase it.
